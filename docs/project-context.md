# プロジェクトの前提

このリポジトリ(プロジェクト)に固有のことを書く。
ハーネスは Angular / Python / Azure の構成を前提にしていて、skill や文書にはその具体名が書かれている([ハーネス](harness/README.md) の「ハーネスの立場」)。ここには、その前提に足すことと、前提と違う点だけを書く。

- skill(`/planning`)は計画の材料としてこの文書を読み、違う点があれば観点の具体名を読み替える。
- 判断の理由は書かない。理由は ADR に書き、ここからはリンクする。今の値(ポート番号など)も書かない。値はコードを見る。

## 何を作るか

Angular のフロントエンドと Python のバックエンドを、セキュアな構成で Azure 上に載せる検証用のプロジェクト。

## 想定する構成と違う点

なし(このリポジトリがハーネスの元なので、想定する構成そのもの。技術選定は [ADR-0001](adr/0001-iac-tool.md)〜[ADR-0003](adr/0003-single-public-entry.md))。

- フロントエンド(`frontend/`)はまだない。最初の画面を作るときに置く。

## インフラが守っていること

インフラのガードレール(何を守っているか、まだ検証できていないこと)は [Azure インフラのガードレール](../infra/docs/azure-infra-guardrails.md) にある。セキュリティ境界の質問の仮の答えは、ここに合わせる。
