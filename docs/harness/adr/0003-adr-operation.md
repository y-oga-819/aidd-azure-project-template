# HADR-0003: ADR は決めた時点の記録とし、判断が変わったら新しい ADR で置き換える

- 状態: 採用（2026-11-14）
- 関連: [ADR の運用ルール](../../adr/README.md)、[HADR-0002](0002-tests-as-specification.md)（文書の役割分担）

## 背景（なぜ決める必要があるか）

ADR は、PR より長く効く判断と捨てた案を残す恒久の文書と位置づけている（HADR-0002）。
しかし、どう更新するかの約束がなかったため、次のことが起きうる。

1. **進み具合や今の値が混ざる。** AI は関連する作業を終えると、ADR に「実装済み」などを書き足しがちになる。進み具合はすぐ古くなり、古い記述を根拠に AI や人が作業してしまう。
2. **判断を変えたときに、変える前の理由が消える。** 書き換えると、PR やほかの文書からのリンクが「リンクした時点とは違う判断」を指すようになる。
3. **状態が意味を持たない。** マージ済みの ADR がすべて「提案」のままで、どれが今も有効か読み取れない。

満たしたいことは、HADR-0002 の要件と同じく「今の正しい判断が 1 か所で分かる」「保守が軽い」こと。

## 選択肢

| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| **A. 決めた時点の記録にし、変わったら新しい ADR で置き換える（採用）** | マージ後は状態の行とリンクだけ直す | 当時の判断と理由がそのまま残る。リンク先の意味が変わらない。書き換えてよい範囲が狭いので、AI に守らせやすい | 判断を変えるたびにファイルが増える。今の判断を知るには状態の行を辿る |
| B. 生きた文書にし、常に最新の判断に書き換える | 変更の経緯は git の履歴で追う | 1 ファイルを読めば今の判断が分かる | 捨てた理由が履歴に沈み、レビューで見えにくい。リンク先の意味が変わる。進み具合を書き足す誘惑を止める線が引けない |
| C. ADR をやめ、判断は PR 概要に残す | PR の「判断と捨てた案」を正本にする | 書く場所が 1 つ減る | PR は探しにくく、GitHub から Azure DevOps へ移ると辿れなくなる |
| D. A に加え、後から分かったことを末尾に追記してよい | 「追記」の節を許す | 判断の背景が補強される | 追記と進み具合の線引きが曖昧になり、1 の問題に戻る |

## 決定

**A を採用する。** 運用ルールは [docs/adr/README.md](../../adr/README.md) に置く。要点は次のとおり。

- 状態は「採用」「置き換え済み」「廃止」。「提案」は PR がレビュー中であることを指し、ファイルには書かない。
- マージ後に書き換えてよいのは、状態の行、リンク切れ、意味を変えない言い回しだけ。
- 判断が変わったら新しい ADR を起こし、古い ADR の状態の行を「置き換え済み」にする。
- 進み具合、今の値、PR やレビューの経緯は書かない。
- 後から分かった事実は、判断が変わるなら新しい ADR に書く。判断が変わらないなら、どこにも書かない。ADR は当時の判断の記録で、最新の事実の置き場ではない。最新の事実はコードと、コードの近くの文書に置く。

### 「提案」をファイルに書くか

| 方法 | 長所 | 短所 |
| --- | --- | --- |
| **ファイルには書かず、PR がレビュー中であることで表す（採用）** | マージの前後で状態の行を書き換える必要がない | ブランチ上のファイルだけを見ると、決まっていない判断も「採用」に見える |
| ファイルに「提案」と書き、マージ直前に「採用」へ書き換える | ファイルだけで状態が分かる | 書き換え忘れが起きる。ADR-0001〜0005 はこのルールより前に「提案」のままマージされた |

決まったかどうかは main にあるかで分かるので、ブランチ上の見え方の問題は小さいと判断した。

## 結果（この判断で受け入れること）

- 判断が変わるたびに ADR が増える。今の判断は、状態が「採用」の ADR だけを読めば分かる。
- 小さな見直しでも、判断が変わるなら新しい ADR を 1 つ書く。重さは、判断を変えた理由を残すための代価と考える。理由が残っていないと、次に同じ議論を繰り返す。言い回しだけの修正や、リンクの追随は書き換えてよいので、新しい ADR が要るのは判断が変わるときだけになる。
- マージ前は自由に書き直してよいので、レビュー中の議論の経緯は ADR に残らない。残すべきなのは捨てた案と理由で、それは「選択肢」に書く。誰がいつ何を言ったかは PR に残る。
- ADR-0001〜0005 はこのルールより前に書いたので、このルールに合わせて状態の行と、進み具合・今の値・経緯の記述だけを直す（判断の中身は変えない）。

## 確かめ方

- AI はルールを守らないことがある。レビューの観点（[review-guide.md](../../review-guide.md)）に入れて、人間が気づけるようにする。それでも漏れるなら、マージ済みの ADR の本文が変わった PR を機械で検出する検査を足す。

## 見直しの条件

- 置き換えの連鎖が長くなり、今の判断に辿り着くのが難しくなった → 置き換え済みの ADR を別のディレクトリに移すなどを検討する
- 状態の行の付け忘れ（置き換えたのに古い ADR が「採用」のまま）が繰り返し起きた → 機械で検査する
